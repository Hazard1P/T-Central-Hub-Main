## Current web physics revision (physics v8)

Flight, prediction/replay, continuous Solar rendering and the authoritative tick now agree on interval endpoint UTC and moving-body positions. High-refresh screens no longer gain simulated time from a minimum frame duration. Moving contact response preserves relative velocity and unspent tangent movement, including Earth surface sliding. Projectile and protected-boundary sweeps use the real segment duration; newly fired pulses cannot hit a player who passed their position before creation. The HTTP adapter enforces a server-selected time budget, and the rigid-body extension samples moving gravity on the same timeline. Body-relative speed is available in Flight physics settings. Matching physics-v8 website/worker deployments are required; no migration or dependency is added.

V8 verification passes 236 tests, 55 API handler checks, the production build and the 536-file source scan with no credential-pattern findings. Normal-rendering browser checks cover flight instruments, coasting, keyboard/native-touch braking and fire, authoritative combat/respawn, shared desktop/phone landing, walking, boarding and 320/390/844px layouts without page/shader errors. An independent solo flow also passes landing, walking and boarding. A five-second local 128-client run sustained 20 simulation ticks/second and rejected overflow; production capacity and physical-device performance remain unverified. See the [physics validation record](PHYSICS-ENGINE.md#continuous-web-physics-physics-v8).

## Previous orbital-to-ground revision (physics v7)

Earth’s orbital silhouette now uses physically bounded relief (under 0.11% of the radius), replacing the earlier exaggerated mountains. The arrival camera faces Earth on initial join. Close exploration transitions into a precise local terrain view and first-person walking without changing room or profile. All Earth render components sample one UTC timestamp per frame, preventing orbital motion from creating metre-scale jitter. Ground tiles keep vertex coordinates close to zero; camera rebasing retains human-scale precision. The live shader uniforms update the atmosphere and globe cutout so close detail is visible.

Land & walk is available near dry ground at low relative speed. E and the visible button use the same server action. The worker validates the living ship, active identity, current movement sequence, altitude, speed and land coverage; client positions/anchors are ignored. It parks the visual ship and anchors the explorer to Earth’s rotating surface. Human eye height is 1.7 m, walking speed 1.6 m/s and sprint capped at 2.8 m/s. Terrain, shoreline, rocks, vegetation and the parked hull footprint constrain walking. Peers receive on-foot state and see avatars and parked ships. Boarding requires returning within 30 m, restores flight at the same ground location and preserves the existing flight/account identity. Old control packets cannot steer the new movement mode. Movement remains transient with the live game service.

The surface uses bundled Earth imagery and original procedural relief, ground materials and natural props. Google Earth is a navigation/view reference here; Google 3D tiles, surveyed elevation, real city buildings and Street View are not connected. No new map-provider credentials, database migrations or package dependencies are needed. Website and worker must deploy together with physics v7.

V7 verification passed 225 automated tests, all 55 API handler checks, the production build and a tracked-source security scan (534 files; no credential-pattern findings). Real signed WebSocket checks cover two clients, shared walking/parked state, stale/spoofed controls and boarding range. Production-build browser checks cover the round orbital globe, first-person descent, keyboard/native-touch walking, shared peers, keyboard/touch boarding and 320/390/844px layouts with no page or shader errors. An independent solo browser flow also passed landing, eye-level walking and boarding. Rendered orbital and ground views were inspected. These are local browser/software-renderer checks; physical-device performance, live provider credentials and production hosting remain separate deployment checks.

## Previous Earth surface revision (physics v6)

The operator requested removal of the landing pads after the v5 integration. The v6 revision removes the ports, buildings, lights, pad occupancy, landing controls and client docking state. An old WebSocket landing request receives a 410 response without changing flight state; the physics-version handshake rejects stale clients. This supersedes the earlier designated-pad feature and its instructions.

Earth itself now contains continuous coastline-masked terrain and oceans in the same universe and room. Five natural waypoints assist exploration, while normal keyboard/mouse/touch controls work anywhere on the surface. The shared height field constrains solo prediction and the authoritative worker, including swept approaches; the chase camera stays above the terrain. The Earth safe zone, account, cargo, rewards and upgrades retain the existing authoritative paths. There is no new database schema or external map provider.
